# 로컬 실행 가이드 (Getting Started)

> 리포지토리를 처음 받는 사람이 순서대로 따라 하면 개발 환경 구성 → 테스트 → 파이프라인/웹서비스
> 실행까지 도달하도록 안내한다. 명령은 복사해서 바로 실행할 수 있게 작성했다.

## 0. 사전 요구사항 (Prerequisites)

| 항목 | 필수 | 비고 |
| --- | --- | --- |
| Python 3.11+ | ✅ | `python3 --version` |
| git | ✅ | 클론 |
| Confluence API 토큰 | 실 수집 시 | 원본 Space 읽기, 신규 Space 쓰기 |
| 로컬 LLM(vLLM 또는 Ollama) | 실 분석 시 | Qwen3-30B-A3B, OpenAI 호환 엔드포인트 |
| TEI(Text Embeddings Inference) | 실 군집/검색 시 | `bge-m3` 임베딩 |
| Postgres + pgvector | 벡터DB 사용 시(선택) | 없으면 파일 기반으로 동작 |

> 외부 서비스(Confluence/LLM/TEI/Postgres)가 없어도 **설치·테스트·개발**은 가능하다(§4, §9).

## 1. 클론 & 가상환경

```bash
git clone https://github.com/kw153stranger/re-confluence.git
cd re-confluence

python3 -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows (PowerShell)
# .venv\Scripts\Activate.ps1
```

## 2. 설치

```bash
pip install --upgrade pip
pip install -e ".[dev]"          # 코어 + 개발 도구(pytest, ruff)

# 선택 확장
pip install -e ".[web]"          # 웹서비스(FastAPI, uvicorn)
pip install -e ".[postgres]"     # pgvector 백엔드(psycopg, pgvector)
```

## 3. 동작 확인 (Smoke Test)

```bash
reconf --help        # 서브커맨드: export/analyze/cluster/build/review/upload/serve
ruff check .         # 린트 → All checks passed!
pytest -q            # 테스트 → 47 passed
```

여기까지 통과하면 코드 기반은 정상이다. 외부 서비스 없이도 전부 통과한다.

## 4. 설정 (Config)

`config.example.yaml`을 복사해 `config.yaml`을 만든다. (`config.yaml`은 `.gitignore` 대상)

```bash
cp config.example.yaml config.yaml
```

주요 키 (`src/reconf/config.py` 기준):

```yaml
source:   { space: "DOCS" }                      # 원본 Space
target:   { space: "RE-ARCHIVE" }                # 신규 Space
llm:      { endpoint: "http://localhost:8000/v1", model: "qwen3-30b-a3b" }
embeddings: { provider: "tei", endpoint: "http://localhost:8080", model: "BAAI/bge-m3" }
cluster:  { sim_threshold: 0.90 }
db:       { backend: "file" }                    # "file" | "postgres"
vault: "./vault"
```

> **비밀값은 파일에 넣지 않는다.** Confluence 토큰 등은 환경변수로 주입한다(§7).

## 5. 파이프라인 실행 (6단계)

각 단계는 독립 실행되며 결과를 `vault/`에 저장한다. 순서:

```bash
reconf export   --config config.yaml --vault ./vault
reconf analyze  --config config.yaml --vault ./vault
reconf cluster  --config config.yaml --vault ./vault
reconf build    --config config.yaml --vault ./vault
reconf review   --export-queue --vault ./vault          # 검수 큐 생성
#  → vault/review_queue.json 을 사람이 확인/수정 후 결정 파일 작성
reconf review   --apply decisions.json --vault ./vault  # 승인/반려 반영
reconf upload   --target-space RE-ARCHIVE --vault ./vault
```

공통 옵션: `--config` · `--vault` · `--resume`(중단 지점부터) · `--dry-run`(쓰기 없이 시뮬레이션).

산출물 위치:

```
vault/
├── raw/          # Export (Markdown + frontmatter) + attachments/
├── analysis/     # Analyze (문서별 JSON)
├── embeddings/   # 임베딩 캐시
├── clusters.json # Cluster (업무→연도 + 중복)
├── labels.json   # 라벨 마스터
├── build/        # Build (페이지 md, tree.json, pages.json)
├── review_queue.json / review.json
└── upload.log
```

> 단계별 **점검 항목**은 [`docs/단계별점검리스트.md`](단계별점검리스트.md) 참고.

### 검수 결정 파일(`decisions.json`) 예시

```json
[
  { "source_page_id": "123456", "status": "approved", "reviewer": "you" },
  { "source_page_id": "123401", "status": "rejected" }
]
```

## 6. 외부 서비스 연결 (실 실행)

실제 수집/분석/업로드를 하려면 환경변수와 엔드포인트를 설정한다.

```bash
# Confluence (원본 읽기 + 신규 Space 쓰기)
export CONFLUENCE_BASE_URL="https://your-org.atlassian.net/wiki"
export CONFLUENCE_EMAIL="you@your-org.com"
export CONFLUENCE_API_TOKEN="********"

# 로컬 LLM (예: vLLM/Ollama OpenAI 호환) — config.yaml llm.endpoint 와 일치
#   vLLM:   python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen3-30B-A3B
#   Ollama: ollama serve  (엔드포인트: http://localhost:11434/v1)

# TEI (임베딩) — config.yaml embeddings.endpoint 와 일치
#   docker run -p 8080:80 ghcr.io/huggingface/text-embeddings-inference --model-id BAAI/bge-m3
```

설정을 마친 뒤 `reconf export …`부터 다시 실행하면 실제 데이터로 동작한다.
원본 Space는 **읽기 전용**으로만 접근하며, 결과는 신규 Space에만 반영된다.

## 7. 웹서비스 실행 (M6)

```bash
pip install -e ".[web]"
reconf serve --vault ./vault           # 기본 http://127.0.0.1:8000
# reconf serve --host 0.0.0.0 --port 9000
```

주요 API (`src/reconf/web/app.py`):

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/api/review/queue
curl -X POST http://127.0.0.1:8000/api/review/decisions \
  -H 'Content-Type: application/json' \
  -d '[{"source_page_id":"123456","status":"approved"}]'
curl -X POST http://127.0.0.1:8000/api/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"구매 정산","top_k":5,"business":"구매관리"}'
```

- `POST /api/runs` · `GET /api/runs/{id}` — 파이프라인 단계 실행/상태
- 의미 검색은 임베딩(TEI)이 필요하다. TEI 없이 API 형태만 보려면 테스트(§9)를 참고.

## 8. 벡터DB (pgvector, 선택)

기본은 파일 기반(`FileVectorStore`)이라 DB 없이 동작한다. 대규모/상시 검색은 Postgres+pgvector 권장.

```bash
pip install -e ".[postgres]"
# Postgres에 스키마 적용
psql "$DATABASE_URL" -f migrations/001_init.sql
```

`config.yaml`에서 백엔드 전환:

```yaml
db:
  backend: "postgres"
  dsn: "postgresql://user:pass@localhost:5432/reconf"   # 비밀은 환경변수 권장
```

> 사내 문서 비유출을 위해 DB·LLM·TEI·앱은 **같은 사내망**에 두는 것을 권장한다(구현설계 §12.4).

## 9. 서비스 없이 전체 흐름 체험

외부 서비스가 없어도 **테스트가 6단계 + 웹 API를 fake 클라이언트로 E2E 검증**한다.

```bash
pytest -q                                  # 전체
pytest tests/unit/test_cluster.py -q       # 예: 군집/중복 탐지만
pytest tests/unit/test_web.py -q           # 예: 웹 API만
```

구현·테스트 구조는 [`docs/구현설계.md`](구현설계.md), 진행 상황은 [`docs/실행태스크.md`](실행태스크.md) 참고.

## 10. 트러블슈팅

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| `오류: Confluence 접속 정보가 없습니다` | `CONFLUENCE_*` 미설정 | §6 환경변수 설정(개발만이면 무시 가능) |
| `오류: 웹 의존성이 없습니다` | web extra 미설치 | `pip install -e ".[web]"` |
| `command not found: reconf` | venv 미활성/미설치 | `source .venv/bin/activate` 후 `pip install -e ".[dev]"` |
| `Address already in use`(포트 충돌) | 8000 사용 중 | `reconf serve --port 9000` |
| import/psycopg 오류 | postgres extra 미설치 | `pip install -e ".[postgres]"` (파일 백엔드면 불필요) |
| 임베딩/검색 실패 | TEI 미기동 | §6 TEI 실행 또는 파일 백엔드 사용 |
