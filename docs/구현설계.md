# Confluence AI 재구성 — 구현 설계서 (Implementation Design)

> 대상 독자: 개발자. `docs/기획서.md`(v3.1)의 아키텍처·IA·스키마를 구현 가능한 수준으로 낮춘 문서다.
> 기술 스택은 **Python**을 기준으로 한다. 핵심 용어·필드명은 영어를 병기한다.

| 항목 | 내용 |
| --- | --- |
| 관련 문서 | `docs/기획서.md`, `docs/실행태스크.md`, `mockups/*.html` |
| 기술 스택 | Python 3.11+ / typer / pydantic v2 / httpx / vLLM·Ollama(Qwen3) |
| 실행 형태 | 단일 CLI(`reconf`), 6단계 서브커맨드, 배치·단방향 |
| 작성일 | 2026-07-09 |

---

## 1. 목적 · 범위 (Scope)

- 기획서 §3~7(아키텍처·단계 설계·IA·라벨 표준)을 **코드로 옮기기 위한 기술 결정**을 확정한다.
- 다루는 것: 스택, 프로젝트 구조, 데이터 모델, CLI 계약, 단계별 함수 설계, 설정, LLM 운영, 테스트.
- 다루지 않는 것(기획서 Non-goals 준수): 원본 파괴적 변경, ACL 자동 이관, 실시간 양방향 동기화.

---

## 2. 기술 스택 & 근거 (Stack)

| 영역 | 선택 | 근거 |
| --- | --- | --- |
| 언어/런타임 | Python 3.11+ | LLM·데이터 처리 생태계, mcp-atlassian 호환 |
| CLI | `typer` | 서브커맨드·타입힌트 기반, 6단계 독립 실행에 적합 |
| 스키마/검증 | `pydantic v2` | Analyze JSON 스키마 강제·직렬화 계약 |
| HTTP | `httpx` | Confluence REST/LLM 엔드포인트 호출(동기+비동기) |
| 수집 | `mcp-atlassian` | 기획서 지정. 페이지·첨부·메타 수집 |
| LLM 서빙 | vLLM **또는** Ollama | 로컬 Qwen3-30B-A3B 서빙(OpenAI 호환 API) |
| 임베딩 | `bge-m3` (`sentence-transformers`) | 본문 유사도 기반 중복 탐지 |
| 제목 유사도 | `rapidfuzz` | 정규화 제목 근사 매칭(빠름) |
| HTML→MD | `markdownify` / `html2text` | Confluence storage/HTML → Markdown |
| 품질/테스트 | `ruff`, `pytest`, `pytest-recording` | lint·포맷·단위/통합 테스트 |
| 설정 | `pydantic-settings` + `config.yaml` | 환경변수·파일 병합 |

> LLM 서빙은 **OpenAI 호환 엔드포인트**로 추상화한다(vLLM/Ollama 교체 가능). 문서 본문은 외부로 전송하지 않는다.

## 3. 프로젝트 구조 (src layout)

```
re-confluence/
├── pyproject.toml
├── config.example.yaml
├── src/reconf/
│   ├── __init__.py
│   ├── cli.py            # typer 진입점: export/analyze/cluster/build/review/upload
│   ├── config.py         # Settings 로더 (pydantic-settings + yaml)
│   ├── models.py         # pydantic 데이터 모델 (§4)
│   ├── store.py          # vault 경로 규칙·읽기/쓰기 (중간 산출물 I/O)
│   ├── llm.py            # OpenAI 호환 클라이언트 + JSON 강제/검증/재시도
│   ├── export.py         # [Export]
│   ├── analyze.py        # [Analyze]
│   ├── cluster.py        # [Cluster]
│   ├── build.py          # [Build]
│   ├── review.py         # [Review] (CLI 반영 + 검수 JSON 입출력)
│   └── upload.py         # [Upload]
└── tests/
    ├── unit/  ├── golden/  └── integration/
```

vault(중간 산출물) 디렉토리는 기획서 §7을 그대로 따른다: `raw/`, `analysis/`, `clusters.json`,
`build/`, `review.json`, `upload.log`.

## 4. 데이터 모델 (pydantic v2)

기획서 §4.2 Analyze JSON 스키마를 모델로 고정한다. `store.py`는 이 모델로만 직렬화/역직렬화한다.

```python
# src/reconf/models.py (요지)
from pydantic import BaseModel, Field

class Confidence(BaseModel):
    business: float; project: float; system: float; year: float

class AnalysisResult(BaseModel):
    source_page_id: str
    title_normalized: str
    business: str | None
    project: str | None
    system: str | None
    year: int | None
    month: int | None = None
    labels: list[str] = Field(default_factory=list)   # 예: "업무/구매관리"
    summary: str
    related_pages: list[str] = Field(default_factory=list)
    duplicate_of: str | None = None
    confidence: Confidence

class ClusterMember(BaseModel):
    source_page_id: str
    role: str            # "canonical" | "duplicate" | "related"
    similarity: float | None = None   # duplicate일 때 0~1

class Cluster(BaseModel):
    business: str
    year: int | None
    members: list[ClusterMember]

class ReviewDecision(BaseModel):
    source_page_id: str
    status: str          # "approved" | "rejected" | "pending"
    overrides: dict = Field(default_factory=dict)  # 사람이 수정한 필드
    reviewer: str | None = None

class PageProperties(BaseModel):     # 기획서 §5.3 표준 필드
    business: str; owner: str | None; system: str | None
    year: int | None; status: str; source: str
```

라벨 네임스페이스(`업무/`·`시스템/`·`연도/`·`상태/`)와 상태값(`정본`/`중복후보`)은 기획서 §5.2·§6을 따른다.

## 5. CLI 인터페이스 (계약)

```
reconf export   --space DOCS [--filter labels=... | --since 2023-01-01]
reconf analyze  [--only PAGE_ID ...] [--model qwen3-30b-a3b]
reconf cluster  [--sim-threshold 0.90]
reconf build
reconf review   [--export-queue | --apply review.json]
reconf upload   --target-space RE-ARCHIVE [--resume]
```

공통 옵션: `--vault ./vault` · `--config config.yaml` · `--resume`(중단 지점부터) · `--dry-run`.

**단계 독립·재실행 규약**: 각 단계는 **이전 단계 산출물만 입력**으로 사용한다(기획서 §7).
예) 프롬프트 개선 → `analyze`부터, IA 규칙 변경 → `build`부터. `--resume`는 완료 항목을
건너뛰고 미처리·실패 항목만 처리한다.

## 6. 단계별 상세 설계

각 단계 공통: **멱등(idempotent)** — 같은 입력→같은 출력, 재실행 시 중복 생성 금지. 구조화 로그 남김.

### 6.1 Export (`export.py`)
- **입력**: Space key, 필터(라벨/기간)
- **처리**: mcp-atlassian로 페이지 목록·본문(storage/HTML)·첨부·메타 수집 → HTML→Markdown 변환 →
  frontmatter(기획서 §4.1) 부착. 페이지네이션·레이트리밋 처리, 첨부는 `raw/attachments/<id>/`에 저장.
- **출력**: `raw/<page_id>__<slug>.md`
- **멱등 키**: `source_page_id`. 수정일 변경 시에만 갱신.
- **핵심**: `export_space(cfg) -> list[RawDoc]`, `to_markdown(storage_html) -> str`

### 6.2 Analyze (`analyze.py` + `llm.py`)
- **입력**: `raw/*.md`
- **처리**: system 프롬프트로 §4 스키마를 강제, 문서 본문+메타를 사용자 입력으로 전달 →
  **JSON 1개**만 수신. 파싱 실패/스키마 위반 시 오류 메시지를 포함해 **최대 N회 재요청**.
  근거 부족 필드는 `null`+낮은 `confidence`. 긴 문서는 청크 요약 후 통합.
- **출력**: `analysis/<page_id>.json` (`AnalysisResult`)
- **핵심**: `analyze_doc(raw) -> AnalysisResult`, `llm.complete_json(schema, prompt) -> dict`

### 6.3 Cluster (`cluster.py`)
- **입력**: `analysis/*.json`
- **처리**: `business`(+`project`)로 그룹핑 → `year`로 하위 그룹핑. 중복 탐지는
  제목 정규화 유사도(`rapidfuzz`) + 본문 임베딩 코사인 유사도. `sim ≥ threshold`(기본 0.90)를
  후보로 표시하고 **정본(canonical)** 은 최신 수정일·최장 본문 등 규칙으로 1개 선정.
  자동 삭제 없음 → 검수로 이관.
- **출력**: `clusters.json` (`list[Cluster]`)
- **핵심**: `build_clusters(results, threshold) -> list[Cluster]`, `pick_canonical(members) -> id`

### 6.4 Build (`build.py`)
- **입력**: `clusters.json`, `analysis/*.json`
- **처리**: 업무 중심 **Page Tree**(업무→연도), 업무별 **Summary(index) 페이지**(Page Properties Report
  매크로 포함), 각 문서 **Page Properties** 블록·**Labels** 생성. 정본/중복 라벨(`상태/*`) 부여.
- **출력**: `build/<page_id>.md` + `build/tree.json`(순서·부모관계)
- **핵심**: `build_ia(clusters, results) -> BuildPlan`

### 6.5 Review (`review.py`)
- **입력**: `build/`, `analysis/*.json`
- **처리**: 검수 큐 export(`--export-queue` → 대시보드용 JSON, `confidence<0.7`·중복후보 우선 정렬),
  사람 수정 결과(`--apply review.json`)를 반영. **승인된 문서만** Upload 대상.
- **출력**: `review.json` (`list[ReviewDecision]`)
- **연계**: 목업 `mockups/pipeline-dashboard.html`의 검수 UI가 이 JSON을 소비/생성하는 형태.

### 6.6 Upload (`upload.py`)
- **입력**: `build/`, `review.json`
- **처리**: 신규 Space 생성 → tree 순서로 페이지 upsert → Page Properties·Labels·Summary 반영 →
  첨부 업로드 → 원본 back-link 삽입. 각 페이지에 `source_page_id` 프로퍼티를 저장해
  재실행 시 **생성 대신 갱신**. 실패는 지수 백오프 재시도 + 실패 목록으로 부분 재실행.
- **출력**: `upload.log` (성공/실패 + 멱등 키 매핑)
- **핵심**: `upsert_page(client, page, existing_map) -> Result`

## 7. 설정 (`config.yaml`)

```yaml
source:
  space: "DOCS"
  filter: { since: "2020-01-01", labels: [] }
target:
  space: "RE-ARCHIVE"
llm:
  endpoint: "http://localhost:8000/v1"   # vLLM/Ollama OpenAI 호환
  model: "qwen3-30b-a3b"
  max_retries: 3
cluster:
  sim_threshold: 0.90
  embedding_model: "BAAI/bge-m3"
labels:
  namespaces: ["업무", "시스템", "연도", "상태"]
vault: "./vault"
```

비밀값(Confluence 토큰 등)은 환경변수로만 주입한다(파일에 저장 금지).

## 8. 로컬 LLM 운영 (LLM Ops)

- **서빙**: vLLM 또는 Ollama를 OpenAI 호환 엔드포인트로 기동. `llm.py`가 엔드포인트만 의존.
- **프롬프트**: system=출력 스키마·규칙(라벨 네임스페이스, null 허용, JSON 1개), user=문서 본문+메타.
- **JSON 강제**: 응답을 `AnalysisResult`로 파싱 → 실패 시 검증 오류를 되먹여 재요청(최대 `max_retries`).
- **검수 우선**: 하나라도 `confidence < 0.7`이면 검수 큐 상단에 노출(기획서 §9 완화책).
- **비유출**: 문서 본문은 로컬 엔드포인트로만 전송, 외부 API 호출 없음.

---

## 9. 로깅 · 관측성 · 재현성

- 구조화 로그(단계·page_id·소요·결과). 각 단계 산출물이 곧 **체크포인트**다.
- 실패 항목은 별도 목록으로 남겨 `--resume`로 부분 재실행.
- 동일 입력·동일 설정 → 동일 산출물(멱등)로 재현성 보장.

---

## 10. 테스트 전략

| 유형 | 대상 | 방법 |
| --- | --- | --- |
| unit | 모델 검증, 유사도, 라벨 생성, canonical 선정 | `pytest`, 순수 함수 |
| golden | Analyze/Build 산출물 | 고정 입력 → 기대 JSON/MD 스냅샷 비교 |
| integration | Export/Upload | **mock MCP**·**mock LLM**(녹화 응답)로 네트워크 없이 |

- LLM은 통합 테스트에서 결정적(mock/녹화) 응답 사용. 실서빙은 수동 스모크 테스트로 분리.

---

## 11. 보안 (Security)

- 로컬 LLM 사용으로 문서 비유출(기획서 §8). 원본 Space는 **읽기 전용** 토큰으로만 접근.
- 민감 문서 제외 훅: 특정 라벨/공간은 Export 또는 Review 단계에서 제외.
- 모든 신규 페이지에 `원본링크(source)` 저장 → 감사(audit) 추적성.
