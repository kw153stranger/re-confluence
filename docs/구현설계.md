# Confluence AI 재구성 — 구현 설계서 (Implementation Design)

> 대상 독자: 개발자. `docs/기획서.md`(v3.1)의 아키텍처·IA·스키마를 구현 가능한 수준으로 낮춘 문서다.
> 기술 스택은 **Python**을 기준으로 한다. 핵심 용어·필드명은 영어를 병기한다.

| 항목 | 내용 |
| --- | --- |
| 관련 문서 | `docs/기획서.md`, `docs/실행태스크.md`, `mockups/*.html` |
| 기술 스택 | Python 3.11+ / typer / pydantic v2 / httpx / vLLM·Ollama(Qwen3) |
| 실행 형태 | 단일 CLI(`reconf`), 6단계 서브커맨드, 배치·단방향 |
| 작성일 | 2026-07-09 |

---

## 1. 목적 · 범위 (Scope)

- 기획서 §3~7(아키텍처·단계 설계·IA·라벨 표준)을 **코드로 옮기기 위한 기술 결정**을 확정한다.
- 다루는 것: 스택, 프로젝트 구조, 데이터 모델, CLI 계약, 단계별 함수 설계, 설정, LLM 운영, 테스트.
- 다루지 않는 것(기획서 Non-goals 준수): 원본 파괴적 변경, ACL 자동 이관, 실시간 양방향 동기화.

## 2. 기술 스택 & 근거 (Stack)

| 영역 | 선택 | 근거 |
| --- | --- | --- |
| 언어/런타임 | Python 3.11+ | LLM·데이터 처리 생태계, mcp-atlassian 호환 |
| CLI | `typer` | 서브커맨드·타입힌트 기반, 6단계 독립 실행에 적합 |
| 스키마/검증 | `pydantic v2` | Analyze JSON 스키마 강제·직렬화 계약 |
| HTTP | `httpx` | Confluence REST/LLM 엔드포인트 호출(동기+비동기) |
| 수집 | `mcp-atlassian` | 기획서 지정. 페이지·첨부·메타 수집 |
| LLM 서빙 | vLLM **또는** Ollama | 로컬 Qwen3-30B-A3B 서빙(OpenAI 호환 API) |
| 임베딩 서빙 | **OpenAI 호환 `/embeddings`** (TEI OpenAI 모드/vLLM) + `bge-m3` | 본문 유사도 기반 중복 탐지. 로컬 서버로 비유출 |
| 제목 유사도 | `rapidfuzz` | 정규화 제목 근사 매칭(빠름) |
| HTML→MD | `markdownify` / `html2text` | Confluence storage/HTML → Markdown |
| 품질/테스트 | `ruff`, `pytest`, `pytest-recording` | lint·포맷·단위/통합 테스트 |
| 설정 | `pydantic-settings` + `config.yaml` | 환경변수·파일 병합 |

> LLM 서빙은 **OpenAI 호환 엔드포인트**로 추상화한다(vLLM/Ollama 교체 가능). 문서 본문은 외부로 전송하지 않는다.

## 3. 프로젝트 구조 (src layout)

```

├── config.example.yaml

│   ├── cli.py            # typer 진입점: export/analyze/cluster/build/review/upload

│   ├── models.py         # pydantic 데이터 모델 (§4)

│   ├── llm.py            # OpenAI 호환 클라이언트 + JSON 강제/검증/재시도
│   ├── embed.py          # OpenAI 호환 임베딩 클라이언트(/embeddings) + 캐시(embeddings/*.json)
│   ├── labels.py         # 라벨 마스터(labels.json) 정규화·유사중복 병합
│   ├── export.py         # [Export]
│   ├── analyze.py        # [Analyze]
│   ├── cluster.py        # [Cluster]
│   ├── build.py          # [Build]
│   ├── review.py         # [Review] (CLI 반영 + 검수 JSON 입출력)
│   └── upload.py         # [Upload]
└── tests/
    ├── unit/  ├── golden/  └── integration/
```

vault(중간 산출물) 디렉토리는 기획서 §7을 따른다: `raw/`, `analysis/`, **`embeddings/`**, `clusters.json`,
`build/`, `review.json`, `upload.log`. 여기에 두 개의 재사용 산출물을 추가한다:
- **`embeddings/<page_id>.json`** — 문서별 임베딩 캐시(§6.3). 재실행 시 재계산을 피한다.
- **`labels.json`** — 전역 라벨 마스터/레지스트리(§6.4a). 유사중복 라벨을 canonical로 통합한다.

## 4. 데이터 모델 (pydantic v2)

기획서 §4.2 Analyze JSON 스키마를 모델로 고정한다. `store.py`는 이 모델로만 직렬화/역직렬화한다.

```python
# src/reconf/models.py (요지)
from pydantic import BaseModel, Field

class Confidence(BaseModel):
    business: float; project: float; system: float; year: float

class AnalysisResult(BaseModel):
    source_page_id: str
    title_normalized: str
    business: str | None
    project: str | None
    system: str | None
    year: int | None
    month: int | None = None
    labels: list[str] = Field(default_factory=list)   # 예: "업무/구매관리"
    summary: str
    related_pages: list[str] = Field(default_factory=list)
    duplicate_of: str | None = None
    confidence: Confidence

class ClusterMember(BaseModel):
    source_page_id: str
    role: str            # "canonical" | "duplicate" | "related"
    similarity: float | None = None   # duplicate일 때 0~1

class Cluster(BaseModel):
    business: str
    year: int | None
    members: list[ClusterMember]

class ReviewDecision(BaseModel):
    source_page_id: str
    status: str          # "approved" | "rejected" | "pending"
    overrides: dict = Field(default_factory=dict)  # 사람이 수정한 필드
    reviewer: str | None = None

class PageProperties(BaseModel):     # 기획서 §5.3 표준 필드
    business: str; owner: str | None; system: str | None
    year: int | None; status: str; source: str

class EmbeddingRecord(BaseModel):    # embeddings/<page_id>.json (재사용 캐시)
    source_page_id: str
    model: str                       # 예: "BAAI/bge-m3"
    dim: int
    content_hash: str                # raw 본문 해시 → 변경 시에만 재계산
    vector: list[float]

class LabelEntry(BaseModel):         # labels.json 항목
    namespace: str                   # "업무" | "시스템" | "연도" | "상태"
    canonical: str                   # 대표 라벨 (예: "구매관리")
    aliases: list[str] = Field(default_factory=list)  # 유사중복 → canonical로 매핑
    status: str = "approved"         # "approved" | "candidate"
    count: int = 0                   # 사용 문서 수

class LabelRegistry(BaseModel):      # 전역 라벨 마스터
    entries: list[LabelEntry] = Field(default_factory=list)
```

라벨 네임스페이스(`업무/`·`시스템/`·`연도/`·`상태/`)와 상태값(`정본`/`중복후보`)은 기획서 §5.2·§6을 따른다.

## 5. CLI 인터페이스 (계약)

```
reconf export   --space DOCS [--filter labels=... | --since 2023-01-01]
reconf analyze  [--only PAGE_ID ...] [--model qwen3-30b-a3b]
reconf cluster  [--sim-threshold 0.90]
reconf build
reconf review   [--export-queue | --apply review.json]
reconf upload   --target-space RE-ARCHIVE [--resume]
```

공통 옵션: `--vault ./vault` · `--config config.yaml` · `--resume`(중단 지점부터) · `--dry-run`.

**단계 독립·재실행 규약**: 각 단계는 **이전 단계 산출물만 입력**으로 사용한다(기획서 §7).
예) 프롬프트 개선 → `analyze`부터, IA 규칙 변경 → `build`부터. `--resume`는 완료 항목을
건너뛰고 미처리·실패 항목만 처리한다.

## 6. 단계별 상세 설계

각 단계 공통: **멱등(idempotent)** — 같은 입력→같은 출력, 재실행 시 중복 생성 금지. 구조화 로그 남김.

### 6.1 Export (`export.py`)
- **입력**: Space key, 필터(라벨/기간)
- **처리**: mcp-atlassian로 페이지 목록·본문(storage/HTML)·첨부·메타 수집 → HTML→Markdown 변환 →
  frontmatter(기획서 §4.1) 부착. 페이지네이션·레이트리밋 처리, 첨부는 `raw/attachments/<id>/`에 저장.
- **출력**: `raw/<page_id>__<slug>.md`
- **멱등 키**: `source_page_id`. 수정일 변경 시에만 갱신.
- **핵심**: `export_space(cfg) -> list[RawDoc]`, `to_markdown(storage_html) -> str`

### 6.2 Analyze (`analyze.py` + `llm.py`)
- **입력**: `raw/*.md`
- **처리**: system 프롬프트로 §4 스키마를 강제, 문서 본문+메타를 사용자 입력으로 전달 →
  **JSON 1개**만 수신. 파싱 실패/스키마 위반 시 오류 메시지를 포함해 **최대 N회 재요청**.
  근거 부족 필드는 `null`+낮은 `confidence`. 긴 문서는 청크 요약 후 통합.
- **출력**: `analysis/<page_id>.json` (`AnalysisResult`)
- **핵심**: `analyze_doc(raw) -> AnalysisResult`, `llm.complete_json(schema, prompt) -> dict`

### 6.3 Cluster (`cluster.py` + `embed.py`)
- **입력**: `analysis/*.json`, `raw/*.md`, (재사용) `embeddings/*.json`
- **임베딩 캐시(재사용)**: 문서별 임베딩을 **파일로 저장**해 클러스터링에 재사용한다.
  - `embed.ensure(page_id, text)` 는 `embeddings/<page_id>.json`(`EmbeddingRecord`)을 확인해,
    **`content_hash`가 일치하면 로드**하고, 없거나 본문이 바뀌었으면 **OpenAI 호환 `POST /embeddings`로 생성 후 저장**한다.
  - 신규·변경 문서만 `embeddings.batch_size` 단위로 배치 임베딩 → 재실행/증분 시 재계산 최소화(`--resume` 친화).
  - 즉, 임베딩은 **실행 단위(문서)별로 캐시 파일에 저장되고 Cluster가 이를 사용**한다.
- **처리**: `business`(+`project`)로 그룹핑 → `year`로 하위 그룹핑. 중복 탐지는
  제목 정규화 유사도(`rapidfuzz`) + 캐시된 본문 임베딩 코사인 유사도. `sim ≥ threshold`(기본 0.90)를
  후보로 표시하고 **정본(canonical)** 은 최신 수정일·최장 본문 등 규칙으로 1개 선정. 자동 삭제 없음 → 검수로 이관.
- **출력**: `clusters.json` (`list[Cluster]`), `embeddings/<page_id>.json`(캐시 갱신)
- **핵심**: `embed.ensure(page_id, text) -> EmbeddingRecord`,
  `build_clusters(results, threshold) -> list[Cluster]`, `pick_canonical(members) -> id`

### 6.4 Build (`build.py`)
- **입력**: `clusters.json`, `analysis/*.json`, `raw/*`(+원본 storage)
- **처리**: **업무 → {개요, 작업실적 → 연도 → 문서}** 3단계 IA 생성(§5.1). 업무별 `BusinessGroup`
  (합성 id `biz-`·`overview-`·`worklog-`, 연도 그룹)과 **개요 본문**(관련 시스템·연도별 문서수 +
  Page Properties Report 매크로)을 만든다. 각 문서 **Page Properties**·**Labels**·정본/중복 라벨 부여.
- **라벨 정규화(마스터 연동)**: 라벨은 §6.4a 라벨 마스터를 거쳐 canonical로 통일한 뒤 부여한다.
- **출력**: `build/<page_id>.md`, `build/pages.json`(문서), `build/tree.json`(BuildTree: 업무·개요·작업실적·연도)
- **핵심**: `build_ia(clusters, analyses, raws, registry, cfg, storages) -> (pages, BuildTree)`,
  `storagefmt.render_overview(business, systems, per_year)`

### 6.4a 라벨 마스터 (`labels.py`) — 전역 라벨 목록·유사중복 방지
문서별로 생성된 라벨이 표기 흔들림(`구매관리`/`구매 관리`/`구매팀`)으로 **유사중복**되지 않도록,
**전역 라벨 마스터 `labels.json`(`LabelRegistry`)** 를 두고 모든 라벨을 canonical로 통일한다.

- **정규화 파이프라인** `resolve_label(ns, raw) -> canonical`:
  1. **정규화**: 공백·대소문자·특수문자 정리 후 네임스페이스 부착(`업무/…`).
  2. **정확 매칭**: 레지스트리의 `canonical`/`aliases`에 있으면 그 canonical 반환.
  3. **유사 매칭**: `rapidfuzz`(표기) + 라벨 임베딩 유사도로 임계값 이상이면 기존 canonical에 **alias로 흡수**.
  4. **신규 후보**: 매칭 실패 시 `status="candidate"` 로 레지스트리에 추가하고 **검수 대상**으로 표시.
- **거버넌스**: `candidate` 라벨은 Review에서 사람이 **승인(→approved)/병합(→기존 canonical의 alias)** 결정.
- **집계**: 각 라벨의 `count`(사용 문서 수)를 갱신해 희소·중복 라벨 정리에 활용.
- **출력**: `labels.json`(갱신). Build/Upload는 이 마스터의 canonical만 사용.
- **핵심**: `resolve_label(ns, raw) -> str`, `merge_alias(canonical, alias)`, `add_candidate(ns, label)`

### 6.5 Review (`review.py`)
- **입력**: `build/`, `analysis/*.json`
- **처리**: 검수 큐 export(`--export-queue` → 대시보드용 JSON, `confidence<0.7`·중복후보 우선 정렬),
  사람 수정 결과(`--apply review.json`)를 반영. **승인된 문서만** Upload 대상.
  라벨 마스터의 **`candidate` 라벨 승인/병합**(§6.4a)도 이 단계에서 처리해 `labels.json`에 반영한다.
- **출력**: `review.json` (`list[ReviewDecision]`), `labels.json`(라벨 거버넌스 반영)
- **연계**: 목업 `mockups/pipeline-dashboard.html`의 검수 UI가 이 JSON을 소비/생성하는 형태.

### 6.6 Upload (`upload.py`)
- **입력**: `build/pages.json`, `build/tree.json`, `review.json`
- **처리**: 신규 Space 생성 후 **IA 계층을 지연 생성**한다:
  업무(`biz-<업무>`, parent=root) → 개요(`overview-<업무>`, parent=업무, 본문=tree의 overview_storage)·
  작업실적(`worklog-<업무>`, parent=업무) → 연도(`year-<업무>-<연도>`, parent=작업실적) →
  **문서(parent=해당 연도 페이지)**. 문서 본문은 원문 storage + Page Properties 매크로(§5.3).
  모든 페이지는 `source_page_id`(문서) 또는 합성 키로 **멱등 upsert**(재실행 시 갱신). 부분 실패 격리.
- **출력**: `upload.log` (성공/실패 + 멱등 키 매핑)
- **핵심**: `_ensure_year_parent(business, year) -> year_page_id`, `writer.upsert_page(...)`

## 7. 설정 (`config.yaml`)

```yaml
source:
  space: "DOCS"
  filter: { since: "2020-01-01", labels: [] }
target:
  space: "RE-ARCHIVE"
llm:
  endpoint: "http://localhost:8000/v1"   # vLLM/Ollama OpenAI 호환
  model: "qwen3-30b-a3b"
  max_retries: 3
embeddings:
  provider: "openai"                      # OpenAI 호환 임베딩(TEI OpenAI 모드/vLLM)
  endpoint: "http://localhost:8080/v1"    # base URL, 경로는 POST /embeddings
  model: "BAAI/bge-m3"
  # api_key: ""                           # 필요 시 Bearer 인증(비밀은 환경변수)
  dim: 1024                               # bge-m3 임베딩 차원
  batch_size: 32                          # 1회 요청 문장 수
  normalize: true                         # 응답을 클라이언트에서 L2 정규화
  timeout_s: 30
  cache: true                             # embeddings/<page_id>.json 재사용(content_hash 키)
cluster:
  sim_threshold: 0.90
labels:
  namespaces: ["업무", "시스템", "연도", "상태"]
  registry: "labels.json"                 # 전역 라벨 마스터 경로
  merge_fuzzy_threshold: 90               # rapidfuzz 표기 유사도(0~100) 이상이면 alias 흡수
  merge_embed_threshold: 0.92             # 라벨 임베딩 코사인 유사도 이상이면 alias 흡수
vault: "./vault"
```

비밀값은 환경변수로만 주입한다(파일에 저장 금지): `CONFLUENCE_BASE_URL`, `CONFLUENCE_PAT`(개인 액세스 토큰).

## 8. 로컬 LLM 운영 (LLM Ops)

- **서빙**: vLLM 또는 Ollama를 OpenAI 호환 엔드포인트로 기동. `llm.py`가 엔드포인트만 의존.
- **임베딩 서빙(OpenAI 호환)**: `bge-m3`를 **OpenAI 호환 `/embeddings`** 서버(TEI OpenAI 모드/vLLM)로 기동하고
  `POST /embeddings`(`{model, input}`) 호출. `embeddings.endpoint/model/api_key/batch_size/normalize`(§7)로 설정.
  응답 `data[].embedding`을 index 순으로 사용, `normalize`면 클라이언트에서 L2 정규화. 문서 본문은 로컬로만 전송(비유출).
- **프롬프트**: system=출력 스키마·규칙(라벨 네임스페이스, null 허용, JSON 1개), user=문서 본문+메타.
- **JSON 강제**: 응답을 `AnalysisResult`로 파싱 → 실패 시 검증 오류를 되먹여 재요청(최대 `max_retries`).
- **검수 우선**: 하나라도 `confidence < 0.7`이면 검수 큐 상단에 노출(기획서 §9 완화책).
- **비유출**: 문서 본문은 로컬 엔드포인트로만 전송, 외부 API 호출 없음.

## 9. 로깅 · 관측성 · 재현성

- 구조화 로그(단계·page_id·소요·결과). 각 단계 산출물이 곧 **체크포인트**다.
- 실패 항목은 별도 목록으로 남겨 `--resume`로 부분 재실행.
- 동일 입력·동일 설정 → 동일 산출물(멱등)로 재현성 보장.

## 12. 웹서비스 & 벡터DB 아키텍처 (M6, 하이브리드)

CLI 배치를 대체하지 않고 **위에 얇게 얹는다**. 6단계 파이프라인 코어(`src/reconf`)는 그대로
라이브러리로 재사용하고(재현성·멱등성 유지), 웹서비스는 **오케스트레이션 + 사람 상호작용(검수) + 검색**만 담당한다.

### 12.1 구성요소
```
[Browser] ── React/정적 프런트 (목업 → 실제 앱: 검수 UI·대시보드·의미 검색)
    │  HTTPS (사내망)
[FastAPI]  ── REST API: 잡 실행/상태, 검수 큐·승인, 라벨 거버넌스, 검색
    │                         │
[Worker(arq/RQ)]          [Postgres + pgvector]
  · 장시간 단계 실행         · 잡/검수/라벨 상태(관계형)
    (export…upload)          · 임베딩 벡터·ANN 검색(pgvector)
    │
[reconf 코어] ── 기존 6단계 함수 그대로 호출 (CLI와 동일 로직)
[로컬 LLM(vLLM/Ollama)] · [TEI]  ── 사내망 내에서만 호출
```

- **백엔드**: FastAPI. 파이프라인 단계는 **동기 실행이 길어** API가 직접 돌리지 않고 **잡 큐(arq/RQ + Redis)** 로 워커에 위임, 진행률은 상태 DB로 폴링/SSE.
- **워커**: `reconf.export/analyze/cluster/build/upload` 함수를 그대로 호출 → **CLI와 코드 공유**.
- **프런트**: 기존 목업(`mockups/*`)을 실제 앱으로 승격. 검수 화면은 `pipeline-dashboard.html`, 공간 조회는 `confluence-space.html` 구조 재사용.

### 12.2 벡터DB (pgvector)
- 파일 캐시 `embeddings/<page_id>.json`(§6.3)을 **pgvector 테이블로 이전(또는 병행)**.
  배치 전용이면 파일 캐시로 충분하지만, **웹 의미 검색·실시간 유사문서 조회**에는 ANN 인덱스가 필요.
- 스키마(요지):
  ```sql
  create extension if not exists vector;
  create table doc_embeddings (
    source_page_id text primary key,
    model text, dim int, content_hash text,
    business text, year int,          -- 메타 필터용
    embedding vector(1024)            -- bge-m3
  );
  create index on doc_embeddings using hnsw (embedding vector_cosine_ops);
  ```
- **검색 API** `POST /search`: 쿼리 임베딩(TEI) → `embedding <=> $1` 코사인 근접 + `business/year` 필터.
- 기존 pydantic 모델과 매핑: `EmbeddingRecord→doc_embeddings`, `LabelRegistry→labels` 테이블, `ReviewDecision→reviews` 테이블. `store.py`에 **파일/DB 백엔드 선택**(`backend: file|postgres`)을 둔다.

### 12.3 API 개요(초안)
| 메서드·경로 | 용도 |
| --- | --- |
| `POST /runs` · `GET /runs/{id}` | 파이프라인 단계 실행·진행 상태 |
| `GET /review/queue` · `POST /review/decisions` | 검수 큐 조회·승인/반려(§6.5) |
| `POST /labels/{ns}/candidates:resolve` | 라벨 후보 승인/병합(§6.4a) |
| `POST /search` | 의미 검색(pgvector) |

### 12.4 배포·보안 (중요)
- **사내망 셀프호스트 전제**: 프런트·API·워커·Postgres(pgvector)·로컬 LLM·TEI를 **같은 사내망**에 배치.
  문서 본문·임베딩이 외부로 나가지 않아야 한다(기획서 §8).
- 외부 관리형(SaaS: Supabase/Vercel 등)을 쓸 경우 **셀프호스트 옵션** 또는 사내 프록시로 비유출을 보장하고,
  최소한 **본문·임베딩은 외부 저장 금지** 원칙을 유지한다.
- 인증/인가(사내 SSO), 검수자 역할(RBAC), 감사 로그를 추가한다.

### 12.5 하이브리드 원칙 요약
- 배치 재현성이 필요한 로직은 **코어에 두고 CLI·웹이 공유**한다(중복 구현 금지).
- 웹은 **사람이 개입하는 지점(검수·라벨 거버넌스·검색)** 에 집중한다.
- 벡터DB 도입은 **검색이 필요할 때만** — 순수 배치는 파일 캐시로 남겨 선택 가능하게 한다.

### 12.6 영속화(저장) 시점·대상 (Persistence model)

모든 저장은 `store.py`를 거치며, **저장 시점은 백엔드(`file`/`postgres`)와 무관하게 동일**하고 **대상만** 파일↔DB로 갈린다.

**저장 원칙**
- **쓰기 단위 = 문서 단위 UPSERT**: 각 단계는 문서를 하나 처리할 때마다 **즉시 저장**(진행 중 저장).
  → 재실행(`--resume`)·진행률 표시·장애 격리를 위해. 집계물(`clusters`)만 **단계 말에 1회** 저장.
- **멱등 키**: `source_page_id`(문서) / `content_hash`(내용) 기준 UPSERT → 재실행 시 중복 레코드 없음,
  임베딩은 `content_hash` 동일하면 재계산·재저장 생략(§6.3).
- **DB 커밋(postgres 모드)**: 문서 단위(또는 소배치) 커밋 → 커밋 즉시 웹 대시보드에서 조회 가능.
- **DB 저장 타이밍**: "배치 종료 후 일괄"이 아니라 **파이프라인이 도는 내내 단계·문서 단위로 계속** 발생한다.

**단계별 저장 시점·대상**

| 단계 | 저장 시점 | file 백엔드 | postgres 백엔드 |
| --- | --- | --- | --- |
| Export | 문서 수집 완료마다 | `raw/*.md`+첨부 | raw 본문·첨부=**파일/오브젝트 스토리지**, 메타=`documents` |
| Analyze | 문서 분석 완료마다 | `analysis/<id>.json` | `analyses` |
| Cluster | 임베딩 생성마다 / 군집은 단계 말 | `embeddings/*.json`, `clusters.json` | `doc_embeddings`(pgvector), `clusters` |
| Build | 문서 빌드 완료마다 | `build/*.md`, `labels.json` | `build_pages`, `labels` |
| Review | 검수자 승인·수정 시 | `review.json` | `reviews`, `labels`(후보 승인) |
| Upload | 업로드 성공/실패마다 | `upload.log` | `upload_results`(+멱등 키 매핑) |
| (M6) 잡 실행 | 실행 중 수시 | — | `runs`(status·progress) 갱신 |

**저장소 분리 규칙**
- **raw 본문·첨부**는 용량이 크고 검색 대상이 아니므로 DB에 넣지 않고 **파일/오브젝트 스토리지**에 두고, DB에는 **경로·메타**만 저장한다.
- **메타·분석·임베딩·군집·라벨·검수·잡 상태**는 DB(임베딩은 pgvector)에 저장해 조회·거버넌스·검색을 지원한다.

> 순수 배치(M2~M5)는 `file` 백엔드로 **DB 없이** 파일에만 저장한다. `postgres` 백엔드는 M6 웹서비스에서 활성화된다.
