# 단계별 점검 리스트 (Stage QA Checklist)

> 각 파이프라인 단계 실행 후 **무엇을 확인해야 하는지**를 정리한 문서다.
> 형식: 점검 항목(무엇을) · 확인 방법(어떻게) · 실패 징후 · 대응.
> 자동 검증은 `pytest`가, 데이터 품질 검증은 이 문서가 담당한다.

## 공통 (모든 단계)
- [ ] 단계 종료 로그에 처리/스킵 건수가 나오는가. (`... 저장 N건, 스킵 M건`)
- [ ] 중간 산출물이 `vault/` 아래에 생성되었는가.
- [ ] 재실행(`--resume`) 시 이미 처리된 항목을 건너뛰는가(멱등).
- [ ] `--dry-run` 이 파일을 쓰지 않고 결과만 보고하는가.

---

## 1. Export (`raw/*.md`)
**목적**: Confluence 원문을 Markdown+frontmatter로 로컬 저장.

| 점검 항목 | 확인 방법 | 실패 징후 → 대응 |
| --- | --- | --- |
| 수집 페이지 수 = 원본 Space 페이지 수 | 로그 `pages=N` vs Confluence 페이지 카운트 | 누락 → 페이지네이션·권한·필터 확인 |
| frontmatter 필수 필드 존재 | `raw/*.md` 상단 `source_page_id/title/updated_at` | 누락 → `_page_to_rawdoc` 매핑 확인 |
| 본문 변환 품질(표·코드·링크) | 샘플 문서 육안 | 깨짐 → `html_to_markdown` 옵션 조정 |
| 첨부 저장 | `raw/attachments/<id>/` 파일 존재 | 없음 → 다운로드 권한·URL 확인 |
| 멱등: 재실행 시 미변경 스킵 | 2회 실행 → `스킵 N` | 매번 재저장 → `updated_at` 비교 로직 확인 |

## 2. Analyze (`analysis/<id>.json`)
**목적**: 로컬 LLM으로 업무/시스템/연도/라벨/요약/신뢰도 추출.

| 점검 항목 | 확인 방법 | 실패 징후 → 대응 |
| --- | --- | --- |
| 전 문서 스키마 통과 | `analysis/*.json` 개수 = raw 개수, 로드 오류 없음 | 검증 실패 → 프롬프트·재시도 확인 |
| `source_page_id` = 입력 id | JSON 필드 대조 | 불일치 → 입력 id 강제 고정 확인 |
| 저신뢰(`confidence<0.7`) 비율 | JSON 집계 | 과다 → 프롬프트·모델·컨텍스트 확인 |
| 라벨이 네임스페이스 형식 | `업무/…`,`연도/…` 포함 | 형식 이탈 → 프롬프트 규칙 강화 |
| 긴 문서 처리 | 대용량 문서 요약 정상 | 절단 손실 → 청크 요약 경로 확인 |

## 3. Cluster (`clusters.json`, `embeddings/*.json`)
**목적**: 업무·연도 그룹핑 + 중복 탐지 + 정본 선정.

| 점검 항목 | 확인 방법 | 실패 징후 → 대응 |
| --- | --- | --- |
| 임베딩 캐시 생성·재사용 | `embeddings/*.json` 존재, 재실행 시 재계산 없음 | 매번 재계산 → `content_hash` 확인 |
| 그룹 수·구성 타당 | `clusters.json` 업무별 그룹 육안 | 과분할/과병합 → 그룹 키·정규화 확인 |
| 알려진 중복쌍 탐지 | 중복 문서가 `duplicate`로 표시 | 미탐지 → `sim_threshold`·유사도 확인 |
| 정본 1개 지정 | 각 그룹 `canonical` 정확히 1 | 오지정 → `pick_canonical` 규칙 확인 |
| 오탐(false positive) | 다른 문서가 중복으로 묶임 | 과탐 → 임계값 상향 |

## 4. Build (`build/*.md`, `build/tree.json`, `labels.json`)
**목적**: 업무 중심 IA·Page Properties·라벨(마스터 정규화) 생성.

| 점검 항목 | 확인 방법 | 실패 징후 → 대응 |
| --- | --- | --- |
| 트리 구조 업무→{개요,작업실적→연도} | `build/tree.json`(business/overview/worklog/years) | 어긋남 → 트리 생성 규칙 확인 |
| 개요 본문 생성 | 각 업무 `overview_storage`에 시스템·연도수·Report 매크로 | 누락 → `render_overview` 확인 |
| Page Properties 표준 필드 | `build/*.md` 프로퍼티 블록 | 누락 → `PageProperties` 매핑 확인 |
| 라벨 canonical 통일 | `labels.json` alias 흡수 | 유사중복 잔존 → 유사매칭 임계값 확인 |
| 신규 라벨 후보 표시 | `status=candidate` 존재 | 무분별 승인 → 후보 흐름 확인 |
| 업무 index/Summary 생성 | 업무별 index 페이지 존재 | 없음 → build_ia 확인 |

## 5. Review (`review.json`, `labels.json`)
**목적**: 사람 검수 — 분류 확인·수정·승인 + 라벨 거버넌스.

| 점검 항목 | 확인 방법 | 실패 징후 → 대응 |
| --- | --- | --- |
| 검수 큐 우선순위 | 저신뢰·중복 후보 상단 정렬 | 뒤섞임 → 정렬 키 확인 |
| 승인 게이트 | 승인 문서만 Upload 대상 | 미승인 유입 → 필터 확인 |
| override 반영 | 수정 필드가 결과에 적용 | 무시됨 → apply 로직 확인 |
| 라벨 후보 승인/병합 | `candidate`→`approved`/alias | 미반영 → 거버넌스 확인 |

## 6. Upload (`upload.log`, 신규 Space)
**목적**: 신규 Space에 멱등 업로드.

| 점검 항목 | 확인 방법 | 실패 징후 → 대응 |
| --- | --- | --- |
| 대상 = 승인 문서만 | 업로드 수 = 승인 수 | 초과 → review 필터 확인 |
| 멱등 upsert | 재실행 시 중복 페이지 없음 | 중복 생성 → `src-<id>` 라벨 조회 확인 (docs/페이지ID관리.md) |
| PUT version | 업데이트 시 `version.number`+1 전송 | 409 Conflict → version 누락 확인 |
| IA 계층 생성 | 업무→개요/작업실적→연도→문서 부모 관계 | 어긋남 → `_ensure_year_parent` 확인 |
| Properties·Labels·원문 반영 | 신규 문서 페이지에 Page Properties 매크로 + 원문 | 누락 → `render_page` 확인 |
| 원본 back-link | 페이지에 원본 링크 | 없음 → 링크 삽입 확인 |
| 원본 Space 불변 | 원본 read-only 확인 | 변경됨 → 쓰기 대상 점검(치명) |
| 실패 부분 재실행 | `upload.log` 실패목록 재처리 | 전체 재업로드 → 재시도 로직 확인 |
