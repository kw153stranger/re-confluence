# Confluence AI 재구성 — 실행 태스크 (Execution Tasks)

> 구현 착수용 마일스톤별 체크리스트. 각 태스크는 `- [ ]`로 관리하고, 마일스톤마다 **DoD(수용기준)** 를 둔다.
> 기술 세부는 [`docs/구현설계.md`](구현설계.md), 배경은 [`docs/기획서.md`](기획서.md) 참고.
> 표기: `⟶ 설계 §x` = 구현설계서 해당 절, `⇒ 산출물` = vault 결과물.

## 마일스톤 개요

| 마일스톤 | 목표 | 선행 | 핵심 산출물 |
| --- | --- | --- | --- |
| **M0** 부트스트랩 | 개발 기반 마련 | — | 리포 구조·CLI 뼈대·CI |
| **M1** 기획·목업 | ✅ 완료 | — | `기획서.md`, `mockups/*` |
| **M2** Export→Analyze→Cluster | 수집·분석·군집 PoC | M0 | `raw/`, `analysis/`, `clusters.json` |
| **M3** Build + Review | IA 생성·사람 검수 | M2 | `build/`, `review.json` |
| **M4** Upload | 신규 Space 반영 | M3 | 신규 Confluence Space, `upload.log` |
| **M5** 하드닝 | 성능·운영·문서화 | M4 | 배치 재수집·성능 개선·백로그 |
| **M6** 웹서비스 + 벡터DB | 코어 재사용 웹서비스·검색 | M3 | FastAPI·pgvector·워커·프런트 |

## M0 — 부트스트랩 (Bootstrap)

**에픽: 프로젝트 기반**
- [ ] `pyproject.toml` 작성 (Python 3.11+, 의존성: typer·pydantic·httpx·rapidfuzz 등) ⟶ 설계 §2
- [ ] `src/reconf/` 패키지 레이아웃 생성 ⟶ 설계 §3
- [ ] `typer` CLI 진입점(`cli.py`) — 6개 서브커맨드 스텁 + 공통 옵션(`--vault/--config/--resume/--dry-run`) ⟶ 설계 §5
- [ ] `config.py` 설정 로더 + `config.example.yaml` ⟶ 설계 §7
- [ ] `models.py` pydantic 모델 정의 (`AnalysisResult`·`Cluster`·`ReviewDecision`·`PageProperties`) ⟶ 설계 §4
- [ ] `store.py` vault 경로 규칙·읽기/쓰기 유틸 ⟶ 설계 §3
- [ ] 구조화 로깅 설정 ⟶ 설계 §9

**에픽: 품질/CI**
- [ ] `ruff`(lint/format) + `pytest` 설정
- [ ] CI 워크플로우(lint + test) 및 `.github/` 세션 훅(선택)
- [ ] `README` 개발 셋업 섹션(설치·실행) 갱신

**DoD (M0)**
- `reconf --help`가 6개 서브커맨드를 표시하고 각 스텁이 실행된다.
- `pytest`·`ruff`가 CI에서 통과한다.
- pydantic 모델이 기획서 Analyze 스키마와 필드·타입이 일치한다.

## M2 — Export → Analyze → Cluster (PoC)

**에픽: Export** ⟶ 설계 §6.1
- [ ] mcp-atlassian 연동으로 Space 페이지 목록·본문·메타 수집 (페이지네이션·레이트리밋)
- [ ] 첨부파일 다운로드 → `raw/attachments/<page_id>/`
- [ ] HTML(storage)→Markdown 변환 + frontmatter 부착 ⟶ 기획서 §4.1
- [ ] 멱등 저장(`source_page_id` 키, 수정일 변경 시 갱신) ⇒ `raw/*.md`

**에픽: Analyze** ⟶ 설계 §6.2·§8
- [ ] `llm.py` OpenAI 호환 클라이언트(vLLM/Ollama 엔드포인트)
- [ ] 분류·요약 프롬프트(system=스키마 강제) 작성
- [ ] JSON 파싱·`AnalysisResult` 검증·실패 재요청(최대 N회)
- [ ] 긴 문서 청크 처리, `confidence` 산출 ⇒ `analysis/<page_id>.json`

**에픽: Cluster** ⟶ 설계 §6.3
- [ ] `embed.py` TEI 클라이언트 + **임베딩 캐시**(`embeddings/<page_id>.json`, `content_hash` 키)
- [ ] 신규·변경 문서만 배치 임베딩, 재실행 시 캐시 재사용(`--resume` 친화)
- [ ] `business(+project)` 그룹핑 → `year` 하위 그룹핑
- [ ] 제목 유사도(`rapidfuzz`) + 캐시된 본문 임베딩 코사인 유사도
- [ ] 임계값 기반 중복 후보 표시 + 정본(canonical) 선정 ⇒ `clusters.json`

**DoD (M2)**
- 샘플 Space에 대해 `export→analyze→cluster`가 오류 없이 완료된다.
- `analysis/*.json` 전수가 스키마 검증을 통과한다.
- 임베딩이 `embeddings/*.json`에 저장되고, 재실행 시 재계산 없이 재사용된다(본문 변경 시에만 갱신).
- 알려진 중복 문서 쌍이 `clusters.json`에서 중복 후보로 잡히고 정본이 1개 지정된다.
- 각 단계가 `--resume`로 부분 재실행된다.

## M3 — Build + Review

**에픽: 라벨 마스터** ⟶ 설계 §6.4a
- [ ] `labels.py` 라벨 레지스트리(`labels.json`, `LabelRegistry`) 로드/저장
- [ ] `resolve_label`: 정규화 → 정확매칭 → `rapidfuzz`+임베딩 유사매칭으로 canonical 통합(alias 흡수)
- [ ] 미매칭 라벨은 `candidate`로 등록, 라벨별 `count` 집계

**에픽: Build** ⟶ 설계 §6.4
- [ ] 업무→연도 Page Tree 생성 + `build/tree.json`(순서·부모관계)
- [ ] 업무별 Summary(index) 페이지 + Page Properties **Report** 매크로 ⟶ 기획서 §6
- [ ] 문서별 Page Properties 블록·표준 필드 생성 ⟶ 기획서 §5.3
- [ ] 라벨을 **마스터 canonical로 정규화**해 부여(`업무/`·`시스템/`·`연도/`·`상태/`) ⇒ `build/*.md`

**에픽: Review** ⟶ 설계 §6.5
- [ ] 검수 큐 export(`--export-queue`): `confidence<0.7`·중복후보 우선 정렬
- [ ] 사람 수정 반영(`--apply review.json`), 승인/반려 상태 관리
- [ ] **라벨 후보(candidate) 승인/병합** 처리 ⇒ `labels.json` 반영
- [ ] 승인 게이트: 승인 문서만 Upload 대상에 포함 ⇒ `review.json`
- [ ] 목업 `mockups/pipeline-dashboard.html` 검수 UI와 JSON 계약 정합성 확인

**DoD (M3)**
- `build/` 산출물이 기획서 IA(업무→연도)·라벨·Page Properties 표준을 따른다.
- 모든 라벨이 마스터 canonical로 통일되어 유사중복 라벨이 생기지 않는다.
- 검수 큐가 저신뢰·중복 후보를 상단에 노출하고, 라벨 후보를 승인/병합할 수 있다.
- `review.json` 승인 결과가 Upload 대상 필터에 반영된다.

## M4 — Upload

**에픽: 신규 Space 반영** ⟶ 설계 §6.6
- [ ] 신규 Space 생성(존재 시 재사용)
- [ ] tree 순서로 페이지 upsert(`source_page_id` 프로퍼티 멱등 키)
- [ ] Page Properties·Labels·Summary 반영, 첨부 업로드
- [ ] 원본 back-link 삽입(추적성)
- [ ] 실패 지수 백오프 재시도 + 실패 목록 부분 재실행 ⇒ `upload.log`

**DoD (M4)**
- 검수 승인 문서가 신규 Space에 업무→연도 구조로 생성된다.
- 재실행 시 중복 페이지가 생기지 않는다(멱등 upsert).
- Page Properties Report / Content by Label 조회가 신규 Space에서 동작한다(목업 대응).
- 원본 Space는 변경되지 않는다(읽기 전용 확인).

## M5 — 하드닝 (Hardening)

- [ ] 대량(수천 페이지) 처리 성능·병렬화·레이트리밋 튜닝
- [ ] 배치 재수집(증분 Export) 지원
- [ ] 운영 문서(Runbook)·트러블슈팅 정리
- [ ] (백로그) ACL·워크플로우 이관, 양방향 동기화 — 기획서 Non-goals, 별도 과제

**DoD (M5)**
- 목표 규모에서 전체 파이프라인이 재현 가능하게 완주한다.
- 운영자가 Runbook만으로 재수집·부분 재실행을 수행할 수 있다.

## M6 — 웹서비스 + 벡터DB (하이브리드) ⟶ 설계 §12

> 파이프라인 코어(`src/reconf`)는 유지하고 그 위에 웹서비스를 얹는다. **사내망 셀프호스트 전제**.

**에픽: 백엔드/오케스트레이션** ⟶ 설계 §12.1·§12.3
- [ ] FastAPI 스캐폴딩 + `reconf` 코어를 라이브러리로 import(중복 구현 금지)
- [ ] 잡 큐(arq/RQ + Redis) 워커: 장시간 단계(export…upload) 비동기 실행
- [ ] 실행/상태 API(`POST /runs`, `GET /runs/{id}`) + 진행률(폴링/SSE)

**에픽: 벡터DB(pgvector)** ⟶ 설계 §12.2
- [ ] Postgres + `pgvector` 스키마(`doc_embeddings` HNSW 인덱스) 마이그레이션
- [ ] `store.py` 백엔드 선택(`file|postgres`) — 임베딩·상태 저장소 추상화
- [ ] **영속화 규칙 구현**(설계 §12.6): 문서 단위 UPSERT(진행 중 저장)·집계물 단계말 저장,
      `source_page_id`/`content_hash` 멱등 키, raw 본문·첨부는 파일/오브젝트 스토리지 분리
- [ ] 임베딩 캐시를 pgvector로 이전(또는 병행) + 메타 필터(`business/year`)
- [ ] 의미 검색 API(`POST /search`): 쿼리 임베딩(TEI) → 코사인 근접 조회

**에픽: 상태·거버넌스 API** ⟶ 설계 §6.4a·§6.5·§12.3
- [ ] 검수 큐 조회·승인/반려(`GET /review/queue`, `POST /review/decisions`)
- [ ] 라벨 후보 승인/병합(`POST /labels/{ns}/candidates:resolve`) ⇒ `labels` 테이블

**에픽: 프런트** ⟶ 설계 §12.1
- [ ] 목업(`mockups/*`)을 실제 앱으로 승격(검수 UI·대시보드·검색)
- [ ] API 연동(잡 상태·검수·검색), 진행률·중복/저신뢰 표시 재현

**에픽: 배포·보안** ⟶ 설계 §12.4
- [ ] 사내망 셀프호스트 배포(프런트·API·워커·DB·LLM·TEI 동일망), 비유출 검증
- [ ] 인증(사내 SSO)·검수자 RBAC·감사 로그

**DoD (M6)**
- 웹에서 파이프라인 단계를 실행·모니터링하고, 검수·라벨 거버넌스를 수행할 수 있다.
- 의미 검색이 pgvector로 동작하고 `business/year` 필터가 적용된다.
- CLI와 웹이 동일한 `reconf` 코어를 공유(로직 중복 없음)한다.
- 문서 본문·임베딩이 사내망 밖으로 나가지 않음을 확인한다.
